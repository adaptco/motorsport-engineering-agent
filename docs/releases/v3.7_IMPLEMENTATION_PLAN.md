# MEA v3.7 Implementation Plan

## Release Intent

v3.7 introduces the first production-grade multi-agent runtime slice on top of the stabilized v3.5.2 kernel baseline.

It does **not** replace the current control plane, telemetry ingest, or forensic ledger surfaces in one cut.
It layers an orchestrated agent runtime beside the existing surfaces, then promotes it behind versioned APIs.

## Grounded Baseline

Current repo state already provides:

- control-plane FastAPI ingress, routing, health checks, and startup validation
- telemetry ingest + runtime log review
- MCP server scaffold with provider status, tool execution, and A2A invoke placeholder
- queue-backed worker execution path
- A2A workflow-state persistence contracts
- forensic ledger + receipt append/replay

This is enough to add v3.7 as an additive release, but not enough to safely “swap in” a multi-agent runtime without a compatibility layer.

## v3.7 Goals

1. Introduce a deterministic **orchestrator service** as the only owner of agent-to-agent routing.
2. Convert the MCP server into a real **gateway** for tools, provider bridges, and A2A invoke.
3. Add a durable **workflow state + handoff state plane** for agent runs.
4. Split contracts out of `shared/models.py` into versioned orchestration / telemetry / eval packages.
5. Add a **HITL evaluation surface** for telemetry-backed approval, rejection, and scoring.
6. Preserve the existing v3.5.2 API surfaces during the migration window.

## Non-Goals

- do not remove the current CI-fix worker loop in this release
- do not migrate all telemetry logic to a cloud-only topology
- do not replace the existing `/runtime/logs/parse` or `/ingest/normalize` flows
- do not make the LLM a source of truth for session or telemetry state

## Release Structure

### Workstream A — Contract Extraction and Versioning

Create:

- `contracts/orchestration/run_envelope.schema.json`
- `contracts/orchestration/agent_spec.schema.json`
- `contracts/orchestration/handoff_event.schema.json`
- `contracts/orchestration/checkpoint_receipt.schema.json`
- `contracts/evals/eval_run.schema.json`
- `contracts/evals/hitl_verdict.schema.json`
- `contracts/telemetry/telemetry_frame.schema.json`
- `contracts/telemetry/evidence_packet.schema.json`
- `contracts/policy/tool_permit.schema.json`

Refactor:

- split `shared/models.py` into:
  - `packages/sdk-models/mea/contracts/orchestration.py`
  - `packages/sdk-models/mea/contracts/telemetry.py`
  - `packages/sdk-models/mea/contracts/evals.py`
  - `packages/sdk-models/mea/contracts/mcp.py`

Acceptance:

- old imports remain valid through compatibility re-exports
- JSON schema bundle generated in CI
- version fields added for all new runtime contracts

### Workstream B — Orchestrator Runtime

Add new service:

- `services/orchestrator/`

Responsibilities:

- run creation
- agent selection
- handoff routing
- checkpoint persistence
- receipt emission
- timeout / retry / dead-letter handling

New API surface:

- `POST /orchestrator/runs`
- `GET /orchestrator/runs/{run_id}`
- `GET /orchestrator/runs/{run_id}/trace`
- `POST /orchestrator/runs/{run_id}/resume`
- `POST /orchestrator/handoffs`

Back-end dependencies:

- PostgreSQL for authoritative run state
- Redis for async dispatch
- forensic ledger for append-only receipts

### Workstream C — MCP Gateway Upgrade

Refactor `mcp_server/` into a versioned gateway.

Add:

- `POST /mcp/v1/tools/call`
- `POST /mcp/v1/providers/invoke`
- `POST /mcp/v1/a2a/invoke`
- `GET /mcp/v1/tools`
- `GET /mcp/v1/providers`
- `GET /mcp/v1/healthz`

Keep compatibility aliases for:

- `/tools/call`
- `/providers`
- `/a2a/invoke`

Behavior changes:

- provider bridge stops returning `scaffolded` and becomes transport-backed
- tool registry becomes metadata-first and policy-aware
- bearer token enforcement is preserved and extended to per-tool permits

### Workstream D — Agent Containers

Add services:

- `services/agent-supervisor/`
- `services/agent-telemetry-analyst/`
- `services/agent-replay-analyst/`

Add configs:

- `config/agents/supervisor.yaml`
- `config/agents/telemetry_analyst.yaml`
- `config/agents/replay_analyst.yaml`

Rule:

- agents do not directly call each other
- all inter-agent coordination goes through orchestrator handoff objects

### Workstream E — HITL Eval Surface

Add service:

- `services/eval-engine/`

Add routes:

- `POST /evals/runs`
- `GET /evals/runs/{eval_id}`
- `POST /evals/runs/{eval_id}/verdict`
- `GET /hitl/sessions/{session_id}/recommendations`
- `POST /hitl/recommendations/{evidence_packet_id}/approve`
- `POST /hitl/recommendations/{evidence_packet_id}/reject`

Add UI:

- `apps/hitl-console/`
- evidence preview
- recommendation queue
- verdict capture
- replay / telemetry attachment inspection

### Workstream F — Deployment and Packaging

Add:

- `deploy/compose/docker-compose.v37.yml`
- `deploy/k8s/`
- `deploy/helm/mea-v37/`

Standardize images to Python 3.12 slim.
Introduce service-level health checks and readiness gating.

## Merge Strategy

### Slice 1
Contracts + compatibility re-exports only.

### Slice 2
Orchestrator service + new DB migrations + API skeleton.

### Slice 3
MCP gateway v1 + legacy alias preservation.

### Slice 4
Agent containers + registry + Redis routing.

### Slice 5
HITL eval engine + UI.

### Slice 6
Deployment manifests, docs, and release notes.

## Database Plan

Additive migrations only for v3.7:

- `004_orchestrator_runs.sql`
- `005_agent_handoffs.sql`
- `006_agent_checkpoints.sql`
- `007_eval_runs.sql`
- `008_hitl_verdicts.sql`

Do not mutate or repurpose current `jobs`, `traces`, or `receipts` tables for agent orchestration in-place.
Keep the legacy CI-fix path isolated.

## Compatibility Guarantees

v3.7 must keep these working:

- `GET /healthz`
- `GET /healthz/dependencies`
- `GET /ingest/sources`
- `POST /ingest/normalize`
- `POST /runtime/logs/parse`
- `GET /runtime/sessions`
- `POST /agent/decision`
- `POST /verifier/execute`

## Exit Criteria

- multi-agent run can complete with at least 3 agents and 2 handoffs
- each handoff emits a persisted checkpoint and ledger receipt
- HITL can approve or reject a recommendation tied to an `evidence_packet_id`
- existing v3.5.2 tests stay green
- new orchestrator / MCP / eval test suites are green
- release docs updated to v3.7

# MEA v3.5.2 Stabilization Plan

## Objective

Lock `v3.5.2 / 0.3.5.2` as the deterministic baseline before structural expansion in v3.6+.

## Scope

- debt flush and baseline hygiene
- compatibility and documentation lock
- runtime confidence retention for existing operator surfaces

## Entry Criteria

- branch baseline points to `v3.5.2 / 0.3.5.2`
- reconciled progress and PRD references exist
- legacy endpoints remain healthy

## Workstreams

### 1. Baseline Hygiene
- complete lint/type safety policy (`ruff` and `mypy` integration)
- close known drift between docs and runtime configuration
- ensure no destructive branch rewrites

### 2. Runtime Stability
- keep existing worker, ingest, verifier, and MCP compatibility behavior
- preserve fail-closed controls and startup validation semantics
- confirm no API contract regressions

### 3. Documentation and Release Lock
- align `PROGRESS.md`, `PRD.md`, and release docs to the same baseline language
- maintain additive migration commitments for later phases

## Compatibility Commitments

No breaking API or schema removals in v3.5.2 stabilization.

Protected endpoints:

- `GET /healthz`
- `GET /healthz/dependencies`
- `GET /ingest/sources`
- `POST /ingest/normalize`
- `POST /runtime/logs/parse`
- `GET /runtime/sessions`
- `POST /agent/decision`
- `POST /verifier/execute`

## Verification

- `python -m pytest -q tests/test_backend_worker.py tests/test_ci_workflow.py tests/test_security_validation.py`
- link and version consistency checks across roadmap docs

## Exit Criteria

- baseline docs synchronized to `v3.5.2 / 0.3.5.2`
- blocker register established for v3.6+ phases
- stabilization checklist complete and recorded in `PROGRESS.md`

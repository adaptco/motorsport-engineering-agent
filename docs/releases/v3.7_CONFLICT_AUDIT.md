# MEA v3.7 Conflict and Downstream Impact Audit

## High-Risk Conflicts

### 1. `shared/models.py` is overloaded
Current state mixes telemetry, ingest, MCP, agent decision, and replay models in one file.

Impact:
- high merge churn
- circular import risk
- poor schema ownership
- hard to version by domain

v3.7 action:
- split by contract domain
- leave compatibility imports in `shared/models.py`

### 2. Current worker is CI-job-centric
`worker/backend_worker.py` assumes queue payloads shaped around repository patch execution.

Impact:
- cannot reuse directly for agent orchestration payloads
- risk of coupling agent runs to CI job lifecycle tables

v3.7 action:
- keep legacy worker intact
- add orchestrator dispatcher + agent workers separately

### 3. Queue design is single-lane
`control_plane/queue.py` uses one queue name: `mea.jobs`.

Impact:
- mixed payload types will collide
- backpressure cannot be isolated by workload class

v3.7 action:
- keep `mea.jobs` for legacy
- add `mea.agent.runs`, `mea.agent.handoffs`, `mea.eval.runs`

### 4. MCP server is scaffold-only
`/a2a/invoke` reports scaffold status rather than executing a real transport-backed provider bridge.

Impact:
- orchestration cannot rely on current MCP service for production dispatch

v3.7 action:
- introduce `/mcp/v1/*`
- preserve old endpoints as compatibility aliases

### 5. DB schema is job-first, not run-first
Current migrations model repo jobs, traces, spans, receipts, and some telemetry evidence tables.

Impact:
- agent orchestration state cannot be safely squeezed into `jobs`
- merge risk if old worker and new orchestrator share mutable semantics

v3.7 action:
- additive migrations for orchestrator/eval state
- no destructive rewrite of existing job tables

### 6. HITL surface is too narrow
Current frontend runtime log review is for CSV/TXT inspection, not reviewable eval workflows.

Impact:
- no operator approval surface for agent recommendations
- no structured verdict or rubric capture

v3.7 action:
- add dedicated eval/HITL routes and console
- keep runtime log review as a sibling tool, not the main console

## Medium-Risk Conflicts

### 7. Docs and branch state drift
v3.5.1 commit resolved merge conflicts and moved the repo to a reconciled baseline, but older local archives still reflect pre-patch state.

v3.7 action:
- branch only from reconciled main baseline
- avoid generating plan files from old `PROGRESS.md` content

### 8. Docker image inconsistency
Images are still Python 3.11 slim in the source archive and called out for standardization in blockers.

v3.7 action:
- standardize all runtime images in one release slice
- validate package compatibility before bump

### 9. File-based A2A state is local-dev friendly, not production-grade
Current background worker persistence writes JSON files under `.mea_tmp/workflow_state`.

v3.7 action:
- keep file persistence as fallback
- move authoritative orchestration state to PostgreSQL

## Downstream Impact Areas

- tests:
  - new integration suites for orchestrator/handoff/evals
  - existing API tests need compatibility coverage
- docs:
  - README
  - CHANGELOG
  - system architecture
  - deployment/runbook/env references
- infra:
  - docker-compose
  - service startup ordering
  - Redis queue isolation
  - database migrations
- observability:
  - traces need run_id / agent_id dimensions
  - receipts need new types for checkpoint/handoff/eval verdict
- release versioning:
  - `pyproject.toml`
  - `VERSION.json`
  - release notes / manifest

## Merge Recommendation

Do not attempt one giant PR.

Use six sequential PRs:
1. contracts
2. orchestrator
3. MCP gateway
4. agents
5. eval/HITL
6. deploy/docs/version bump

That keeps `main` mergeable and lets legacy surfaces remain stable through the transition.

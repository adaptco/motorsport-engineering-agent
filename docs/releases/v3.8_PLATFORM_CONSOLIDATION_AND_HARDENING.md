# MEA v3.8 Platform Consolidation and Hardening Plan

## Objective

Ship a hybrid v3.8 release that executes in this order:

1. platform consolidation
2. capability expansion through toolized skills (`SKILL.md` pattern)
3. production hardening as a mandatory gate

## Scope

- simplify and formalize service/package ownership boundaries
- package capabilities via governed skill and tool contracts
- close reliability, observability, rollback, and SLO readiness gaps

## Workstreams

### Workstream A — Platform Consolidation First

- rationalize app/service boundaries and dependency ownership
- reduce duplicate contract and model definitions
- finalize canonical package and deployment ownership map

### Workstream B — Capability Expansion via Skills

- add toolized capability surfaces driven by `SKILL.md`
- define skill contract versioning and validation rules
- ensure capability growth passes policy and contract gates

### Workstream C — Production Hardening Gate

- define service-level SLOs and error budgets
- enforce observability dimensions (`run_id`, `agent_id`, lane-level metrics)
- establish rollback and incident playbooks
- validate reliability and regression gates before release close

## API and Contract Commitments

- maintain compatibility for critical v3.5.2-v3.7 endpoints
- add new capabilities through versioned interfaces and explicit compatibility windows
- keep migration additive; no destructive rewrites

## Verification

- platform integration suite across orchestrator, MCP v1, eval/HITL, and legacy compatibility routes
- skill tooling contract suite (`SKILL.md` parser/validator + policy checks)
- reliability suite covering retries, fallback behavior, checkpoint resume, and rollback drills

## Exit Criteria

- consolidated platform ownership documented and implemented
- capability expansion shipped through governed skill tooling
- production hardening gates met (SLO, observability, rollback readiness)

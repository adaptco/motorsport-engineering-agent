## Checkpoint purpose

Capture a bounded, testable path from the current V3.5 infrastructure toward a working prototype that produces useful iRacing session outputs instead of raw telemetry dumps.

This checkpoint does not change the PRD mandate that the repository is still in a production-readiness review and remediation phase. It defines the shortest deterministic prototype loop that can be validated quickly.

## Useful output definition

For iRacing, useful output means processed session analysis rather than raw telemetry.

Expected prototype outputs:

- lap delta vs best
- braking consistency
- throttle trace quality
- corner time loss ranking
- tire or load behavior trends when available
- coaching suggestions such as:
  - brake 8-10m earlier T1
  - over-rotating mid-corner T5
- session summary:
  - fastest lap
  - consistency score
  - incident markers

## Current state

Available now:

- ingest framework and normalization direction from V3.5
- control-plane scaffolding
- static-log routing surface

Still missing:

- iRacing IBT parser wired into the ingest pipeline
- canonical telemetry schema fully enforced for prototype analysis
- derived feature extraction layer
- analysis API returning ranked issues and session summary
- GUI bound to processed outputs

## Critical blocker

The main blocker is not MCP, ANP, ACP, or the LLM.

The missing layer is:

`Telemetry -> Features -> Insights -> UI`

Without feature extraction, the stack remains a file conversion path with no actionable outputs.

## 48-72 hour prototype loop

### Day 0

Define and lock:

- canonical schema for the prototype path
- IBT parser contract
- session analysis output contract

### Day 1

Build:

- `ingest/logs/adapters/iracing_ibt.py`
- canonical field normalization for:
  - `timestamp_ns`
  - `speed`
  - `throttle`
  - `brake`
  - `steering`
  - `lap`
- deterministic feature extraction:
  - lap segmentation
  - braking zones
  - throttle ramps
  - basic corner detection heuristic

Target output shape:

```json
{
  "laps": [],
  "corners": [],
  "events": []
}
```

### Day 2

Build:

- delta vs best lap
- braking variance
- throttle smoothness
- corner loss ranking
- analysis API:
  - `GET /session/{id}/analysis`

Target response shape:

```json
{
  "summary": {},
  "top_issues": [],
  "lap_times": []
}
```

### Day 3

Build a minimal GUI with:

- lap chart
- throttle/brake traces
- corner ranking list
- summary panel

Recommended stack:

- React or Next.js frontend
- fetch from `/session/{id}/analysis`

## Acceptance criteria for the first working prototype

1. User uploads or points to an IBT file.
2. System parses the file without transcript-based reasoning.
3. System emits deterministic analysis artifacts.
4. API returns summary, lap deltas, and ranked issues.
5. GUI renders:
   - lap chart
   - throttle/brake traces
   - corner ranking
   - summary panel
6. At least one session produces actionable coaching text from deterministic metrics.

## Scope guardrails

Do not expand during this prototype loop:

- no multi-sim support yet
- no real-time loop yet
- no voice output yet
- no LLM-derived analysis in the critical path
- no broad MCP expansion before features exist
